# E021：门控 G2b，未中心化分库接入真实 Metis 的闭环删除组合测试

设计：`docs/design_G2b.md`（预先登记）。实现：`src/holistic/banked_metis.py`（不修改 `metis/`）。
回归：`regression_G2b0.py`（G2b-0，分库代码路径与 install_rls 逐位一致，已在最终代码上重跑通过）。
主实验：`run.py`（20 条新 episode，seed 9400）。结果：`result.json`。

结构（等总状态）：每层 K=4 库，键 256 维（PCA 基由 seed 9000 前 10 条拟合），值 1024 维，RLS λ=0.9；路由不中心化（随机固定中心，位于 PCA 子空间）。零样本（预训练模型，未训练）。

## 判定（按 design_G2b.md §6）

- G2b-0（实现回归）：通过（重跑）。
- G2b-1（B 精确，状态误差 < $10^{-3}$）：通过。
- G2b-2（B − 参考的区间在 [−0.1, +0.1] 内）：通过。
- **G2b 机械上通过。**

## 必须说明的限制（这些决定了结论的力度）

1. **B 的通过是构造性的**：B 是参考的一个等价实现。它验证的是实现正确、成本可接受，不是一个需要检验的科学假设。
2. **负载集中**：本次通过的分库实际上接近"一个大库 + 少量小库"，即接近单库加少量额外状态。因此 G2b 的机械通过**不能**用来支持"分库有组织收益"。收益需要负载均衡的分库，而这依赖于中心的选择。
3. **A（降秩）在较早 chunk 上失效**：误差大，并且在 c=2 时数值爆炸（病态的 $P$ 求逆）。降秩不能用作删除机制，这与 G2 的结论一致（N10）。
4. **答案 NLL 无分辨力**：A 的状态误差很大，但 NLL 区间包含 0（E020 也有同样问题）。
5. 零样本：分库结构未训练，与预训练读出不匹配（E015a）。本门控只检验组合的删除机制，不评价回答质量。

## 结论与下一步

- 机制层面：**未中心化分库 + RLS + 快照重放删除**在真实闭环模型中可以精确实现，成本低于完整重放。
- 组织层面：本次抽取的中心导致负载集中，分库的收益无法确定。下一步需要：
  (a) 多个中心抽取下的负载分布（稳健性）；
  (b) 若负载不稳健，考虑负载均衡的机制（例如中心的选择准则，或学习路由，见设计 0a §12 中关于"路由是唯一学习部分"的原则）。
- A 应从删除候选中移除（或限定为最后一个 chunk 的特例）。
