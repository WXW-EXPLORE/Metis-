# E015：RLS 直接装到预训练 Metis-4B 的零样本代价，以及删除测试

脚本：`run.py`。结果：`result.json`。

## (a) 零样本代价（已测）

对 30 条验证 episode（未见词表），答案 token 的平均 NLL：

| 设置 | NLL |
|---|---|
| 预训练 GDN（原版，不训练） | **10.14** |
| RLS 直接替换（不训练） | 12.58 |
| 无记忆 | 14.16 |

**结论（已验证）**：直接替换不是改进。RLS 比预训练 GDN 差约 2.4 nats，但比无记忆好约 1.6 nats。
代价在于：预训练的读出、`mem_norm`、query 投影都是为 GDN 的状态动力学训练的，替换后它们与新的记忆内容不匹配。
要获得 RLS 的收益，需要像 1b 那样从头训练（或至少重新训练记忆参数），而不能直接替换。

## (b) 删除测试（已测，10 条 episode）

删除包含答案的那个 chunk，使用 RLS 的降秩（权重 $\lambda^{\text{age}}$）。参考为"从未写入该 chunk"的 replay。

| 指标 | 结果 |
|---|---|
| 删除后答案 NLL | 15.40 |
| 参考（从未写入该 chunk）NLL | 15.85 |
| 删除前答案 NLL | 12.43 |
| 无记忆 NLL | 14.88 |
| 状态相对误差（最大层，均值） | 0.64 |

**结论（已验证，含修正）**：

1. 降秩公式本身正确：给定**同样的写入输入**，双精度降秩与参考的误差约 $3\times10^{-5}$（第 0 层与第 7 层均验证）。
2. 但在真实模型中，删除**不精确**：较深的记忆层（如第 7 层）的参考与降秩结果相差约 0.66。原因是记忆是闭环的：较早层的记忆读出影响后续层的隐藏状态，从而改变后续写入的键。删除一个 chunk 后，这些键不再与原来相同，而降秩假设它们不变。
3. 因此，我之前关于"RLS 删除精确"的结论**只在参考模型、固定输入下成立**，在训练后的 Metis 中不成立。这个结论需要修正。
4. 答案的似然上，删除后（15.40）接近参考（15.85），说明降秩大体上去掉了目标信息，但不是精确的。

## 与 GDN 的比较

GDN 没有寻址删除接口，因此没有做 GDN 的删除对照。若要删除，只能重算（replay 不含该 chunk），这是精确的，但代价是完整的重算。
RLS 的降秩比重算便宜，但在闭环系统中只是近似。

- 设计 0a 的 C 模块（显式删除）需要据此修订：降秩只适用于开环（固定输入）场景。
