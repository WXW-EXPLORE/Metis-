# E019：门控 G1b，未中心化路由，等总状态，新测试数据

设计（预先登记）：`docs/design_G1b.md`。脚本：`run.py`。结果：`result.json`。
测试集：新的 20 条 episode（seed 9100），E018 未使用。PCA 基仍由 seed 9000 的前 10 条拟合。
路由：`argmax_b k̂·c_b`，k̂ 为单位化的原始键，c_b 为随机固定中心（不使用任何数据统计量）。

## 判定

- **G1b 通过**（预先登记的判据：两层的两个配对差区间下界均 > 0）。
- 负载均衡：未出现 E018 中担心的负载集中。因此"有效库变大"不能解释这一结果。

## 解释与限制（必须报告）

1. 随机分库的库数与维度与 K4_raw 相同，所以差异来自**键的内容分配**，而不是分库本身。
2. 收益相对单库较小（层 7 仅 +0.005）。
3. 测试集只有 20 条 episode，指标是自检索余弦，不是问答正确率。
4. 等总状态：每库 256 维 PCA 键，K1 与 K4 的总状态都是 1024×1024。但 K4 每库的协方差较小（256×256），这是等状态下的正常结果。
5. 随机中心未训练；路由不中心化，因此路由没有使用任何数据统计量。

## 与 E018 的关系

E018 的预先指定路由是中心化的，未通过 G1（N12）。E019 按你的指示改为不中心化，并使用新测试集，通过了 G1b。
这次改变是路由定义的改变（去掉中心化），不是在同一数据上换判据；E018 的记录保持不变。
