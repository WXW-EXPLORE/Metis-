# E016：真实 Metis 的写入键分布（第二步路由的前置诊断）

脚本：`run.py`（结构统计）、`route_test.py`（路由均衡）。结果：`result.json`、`route_test.json`。
数据：LoCoMo 之外的合成验证 episode（10 条，用于结构统计；3 条，用于路由测试）。键取自预训练 Metis-4B 各记忆层的写入键。

## 1. 键的结构（已验证）

| 层 | 键数 | 有效秩（参与比） | 前 16 主成分方差 | 前 64 主成分方差 | 两两余弦均值 |
|---|---|---|---|---|---|
| 0 | 1458 | 5.2 | 0.86 | 0.96 | +0.37 |
| 1 | 1458 | 15.1 | 0.73 | 0.92 | +0.17 |
| 3 | 1458 | 5.4 | 0.82 | 0.95 | +0.38 |
| 7 | 1458 | 7.5 | 0.70 | 0.88 | +0.32 |
| 各向同性参考 | 2000 | 676.6 | 0.04 | 0.16 | 0.00 |

（层 2、4、5、6 见 `result.json`，范围一致。）

**结论**：真实键是**极低秩**的，且有一个共同的主方向（余弦均值为正）。这与各向同性的合成键完全不同。
- 这正是 RLS 协方差膨胀和崩溃的情形（N8、N9）：未激励方向的协方差会随遗忘增长。
- E006–E008 的路由与分库结论（基于各向同性键）**不能直接外推到真实模型**。

## 2. 路由均衡：未中心化 vs 中心化（已验证）

硬路由 top-1，随机固定中心（未训练），3 条 episode。

| 层 | 未中心化：最大库占比 / 归一化熵 | 中心化后：最大库占比 / 归一化熵 |
|---|---|---|
| 0 | 0.49 / 0.84 | 0.31 / 0.98 |
| 3 | 0.65 / 0.65 | 0.29 / 0.99 |
| 7 | 0.47 / 0.89 | 0.30 / 0.99 |

**结论**：未中心化时路由明显不均衡（共同方向让多数键落入同一库）。减去键的均值（一个固定的解析变换，不需要学习）后，路由近似均匀。

## 3. 对设计的含义

- 路由（模块 E）的输入应使用**中心化后的键**。这是一个解析预处理，符合"经典理论已给出的部分不学习"的原则。
- 由于键是低秩的，分库（模块 A）的价值需要重新评估：合成键上的结论（E006–E008）不适用。
- 中心化后，是否还需要负载均衡损失，需要在真实键上用学习的中心进一步测试。
- 路由是否真的减少串扰，尚未验证（这里只测了均衡性）。
