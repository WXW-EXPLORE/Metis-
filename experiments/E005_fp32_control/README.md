# E005：Phase 0b fp32 状态对照

设计：`docs/design_phase0b_fp32.md`。实现：`src/diagnostics/gate_ablation.py`（`precision="fp32"`，读出包裹）。单元测试：`tests/test_gate_ablation.py`（10 项通过）。

复现（激活 `/hy-tmp/venv-metis`，仓库根目录）：

```bash
PYTHONPATH=.:src python experiments/E004_erase_forget_ablation/run_ablation.py \
  --checkpoint_path /hy-tmp/metis-models/Metis-4B \
  --memqa_file eval/data/memqa/locomo_evidence_sessions_tps16_20260626.jsonl \
  --max_sessions 100 --seed 0 --precision fp32 \
  --out experiments/E005_fp32_control --raw_dir /hy-tmp/metis-outputs/E005
python experiments/E005_fp32_control/compare.py
```

设置与 E004 完全相同（同一 100 个会话，247 个问题，同样的 4 种模式），只改变状态的存储与递推精度（bf16 → fp32）。

## 结果

### 各模式平均 NLL（fp32）

| 模式 | 平均 NLL | 配对差（相对 fp32 full） | 95% bootstrap 区间 |
|---|---|---|---|
| full | 4.4012 | — | — |
| no_erase | 4.3972 | **−0.0040** | **[−0.0082, −0.0002]** |
| no_forget | 4.8295 | **+0.4283** | **[+0.3180, +0.5560]** |
| none | 6.5132 | **+2.1120** | **[+1.8306, +2.4155]** |

### 配对比较（`compare_bf16_fp32.csv`）

| 对比 | 均值 | 标准误 | 95% 区间 |
|---|---|---|---|
| 精度效应：full(fp32) − full(bf16) | +0.0020 | 0.0027 | [−0.0031, +0.0075] |
| 擦除效应（fp32）：no_erase − full | −0.0041 | 0.0020 | [−0.0082, −0.0004] |
| 擦除效应（bf16，E004）：no_erase − full | +0.0005 | 0.0018 | [−0.0030, +0.0041] |
| 擦除效应的差：fp32 − bf16 | −0.0045 | 0.0027 | [−0.0101, +0.0004] |

### 状态统计

每层擦除相对大小（`erase_rel_mean`）在 bf16 与 fp32 下几乎相同（例如第 27 层均为 $2.6\times10^{-5}$），与 E004 一致。擦除的量级在两种精度下没有变化。

## 判定

按设计文档 §5 预先约定的规则：

- "fp32 下 no_erase 区间包含 0"：**不满足**（区间 [−0.0082, −0.0002] 不含 0）。
- "fp32 下 no_erase 区间明显大于 0"：**不满足**（区间在 0 以下）。

**这一结果落在预先约定的两类之外。** 我的规则只考虑了“擦除有益”和“无作用”两种情形，没有考虑方向相反的显著效应。因此下面的解释是事后判断，需要读者留意：

1. 擦除的效应在统计上可测，但**方向是有害的**：去掉擦除后答案 NLL 略降，幅度约 0.004 nat/token。
2. 这一效应**只有 0.1% 量级**，约为遗忘效应（+0.43）的 1%。
3. "精度导致擦除效应消失"的假设**没有得到支持**：两种精度下擦除效应的差 −0.0045，区间 [−0.0101, +0.0004] 包含 0。bf16 下的 "无作用" 与 fp32 下的 "微弱有害" 在统计上没有显著区别。

## 与 E004 的关系

- E004 的结论"按键擦除对读出没有可测贡献"需要修正为：**按键擦除对读出的贡献很小（约 0.004 nat/token），在 fp32 下可测，方向为轻微有害，在 bf16 下与 0 无显著差别。**
- 遗忘的作用（+0.43）不受精度影响，仍然是主要贡献。
- 思路三的核心判断不变：按键擦除作为增量的价值很小。

## 单元测试揭示的机制

`tests/test_gate_ablation.py` 中的 `test_erase_survives_in_fp32_and_is_rounded_away_in_bf16` 证明：在构造的小擦除情形下，bf16 存储会把擦除舍入掉（full 与 no_erase 的状态逐位相等），fp32 则保留它（与参照的相对误差约 1%，受 fp32 绝对精度限制）。也就是说，bf16 确实会抹去擦除项，但在真实模型中，这一抹除并没有显著改变答案的似然。

## 限制

1. **单一会话子集**（种子 0，100/568 个会话）。按 CLAUDE.md，结论需要多个子集种子复核。擦除效应的置信区间较宽，多个种子才能确定方向。
2. **只测了 NLL**，没有测生成答案的正确率。
3. **精度对照只改变状态**，不改变投影层与读出之后的计算。bf16 的其他部分（如 o_proj）仍然是 bf16。
4. **统计的是 teacher-forced 的答案似然**，与真实生成的行为可能有差异。

## 多子集复核（种子 1、2，fp32）

| 子集 | n（QA） | no_erase − full | 95% 区间 |
|---|---|---|---|
| 种子 0（上文） | 247 | −0.0041 | [−0.0082, −0.0004] |
| 种子 1 | 253 | +0.0003 | [−0.0040, +0.0046] |
| 种子 2 | 259 | −0.0003 | [−0.0047, +0.0040] |
| 合并（唯一 QA） | 634 | −0.0021 | [−0.0049, +0.0007] |

复现：`experiments/E005_fp32_control/seed1/`、`seed2/` 为对应的 `run_ablation.py` 输出；`aggregate_seeds.py` 生成 `aggregate_seeds.csv`。

**注意**：三个子集之间约有 45 个 QA 重叠，合并估计不是独立样本，只作参考。

## 更新后的结论

- **种子 0 的"轻微有害"没有复现。** 种子 1、2 的擦除效应都与 0 无显著差别，合并估计也包含 0。
- 擦除对答案 NLL 的效应在 ±0.005 nat/token 以内，统计上与 0 无法区分。与遗忘效应（约 +0.40）相比，约为 1% 以下。
- 精度（bf16 vs fp32）不影响这一结论。
- 因此，按键擦除对读出的贡献**不可测或极小**。E004 的原始表述"没有可测贡献"在三个子集上基本成立，但需要注明：种子 0 单独看有边缘显著的负效应，这一点没有被其他子集确认。

## 对思路三的含义

按键擦除作为读出层面的机制，在训练后的 Metis 中贡献很小。如果后续要保留思路三，目标应当是检验"删除与遗忘分离"能否带来可测收益，而不是改进按键擦除本身。这需要单独设计，尚未验证。
