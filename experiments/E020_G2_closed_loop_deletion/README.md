# E020：门控 G2，闭环删除的组合测试（真实 Metis-4B，RLS 单库，λ=0.9）

设计（预先登记）：`docs/design_G2.md`。脚本：`run.py`。结果：`result.json`（汇总与逐 episode）。
数据：seed 9200，20 条新 episode。被删 chunk 为包含答案的最后一个 chunk。

## 结果

| 机制 | 状态误差（相对参考） | 说明 |
|---|---|---|
| B 快照加下游重放 | **0.0**（所有 episode） | 与"从未写入该 chunk"的参考逐位一致；平均重放 3.1 个 chunk（会话平均 5 个） |
| A 降秩（近似） | 0.46（平均） | 被删为最后一个 chunk 时约 0；被删为较早的 chunk 时显著增大（c=0 时 0.89） |

按被删位置的 A 误差：c=0：0.885；c=1：0.571；c=2：0.409；c=3：0.388；c=4：0.000。这与 N10 的闭环机制一致：越早的 chunk，它之后的写入越多，降秩的误差越大。

答案 NLL（配对差，相对参考，区间为 bootstrap 95%）：

| 比较 | 均值 | 95% 区间 |
|---|---|---|
| 完整会话 − 参考 | −1.78 | [−2.36, −1.22] |
| A − 参考 | −0.25 | [−0.73, +0.19] |
| B − 参考 | 0.00 | [0.00, 0.00] |
| 无记忆 − 参考 | −0.58 | [−1.76, +0.55] |

## 判定（按 design_G2.md §5）

- B 精确（状态误差 < $10^{-3}$）：**满足**（最大值 0.0）。
- B 删除有效（B−参考的区间在 [−0.1, +0.1] 内）：**满足**（区间为 [0, 0]）。
- **G2 通过**。

## 必须说明的限制

1. **B 的通过基本是构造性的**：B 就是参考的一个等价实现，只要实现正确就一定与参考一致。它的价值在于证明精确删除是可实现的，并给出成本，而不是一个需要检验的科学假设。
2. **答案似然的分辨力不足**：A 的状态误差很大（平均 0.46），但 A−参考的 NLL 区间包含 0。所以这个指标无法区分近似删除与精确删除。G2 的判据之所以能用它，是因为 B 本身就是精确的。
3. 完整会话比参考的 NLL 低 1.78（区间不含 0），说明被删信息确实对答案有贡献，删除有实际效果。
4. 路由未纳入真实模型（单库 RLS）。未中心化路由的组合是 G2b，需要先把分库接入 Metis 的记忆层。
5. 成本：B 需要保存每个 chunk 的快照（每层约 8MB，8 层约 64MB/快照），以显存换计算。
