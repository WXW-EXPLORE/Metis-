# E025（G1e）：训练后的读出下，分库是否优于单库

状态：**已完成，G1e 未通过**（2026-10-21）。结论记录为 N16（`docs/negative_results.md`）。结果见第 4.4 节。
设计依据：`docs/design_G1e.md`（§10、§11 为运行前修订）、`docs/design_readout_norm.md`。

---

## 1. 为什么做这个实验

之前的 G1d 实验测的是"路由本身"：拿一个不训练的模型，只看把键分到几个库之后，自检索能不能更好。结果是分库没有优势（N15）。

但这里有一个漏洞：模型的读出（从记忆里取东西的那一部分）从来没有训练过。也就是说，即使键被分得很好，读出也可能不会利用这种分法。如果是这样，"分库没有收益"只说明"没有训练的读出用不上分库"，并不说明分库本身没用。

所以这个实验做一件更公平的事：**让记忆和读出一起从头训练**，然后比较三种结构在同样预算下的效果。

用大白话说：
- 单库：把所有内容放在一个大记忆里。
- 分库（学习的原型）：把内容分到 4 个小记忆里，分法由数据学出来。
- 分库（随机）：同样 4 个小记忆，但分法是随机的。作为对照，看"分得好"是否真的比"随便分"强。

## 2. 配置

| 项目 | 设置 |
|---|---|
| 模型 | Metis-4B，骨干冻结，只训练记忆部分 |
| 记忆层 | 8 层（全部记忆层） |
| 读出分母 | `1+|q·z|`（修正版，见 `docs/design_readout_norm.md`） |
| 三个臂 | K1_full（单库 1024×1024）；K4_CL_cons（4 库，每库 256×1024，原型由竞争学习得到）；K4_random（4 库，随机中心） |
| 等状态 | 三个臂的总状态相同（1024 行） |
| 等参数 | 三个臂的可训练参数相同（125,884,416） |
| 训练数据 | LoCoMo 对话，前 5 个对话，去掉超过 3000 token 的 episode，剩 712 个 QA 行 |
| 测试数据 | 后 5 个对话，共 771 个 QA 行；每次评测用前 100 行 |
| 训练步数 | 300 步，每步累积 4 个 episode，学习率 1e-4（带 warmup 与余弦衰减） |
| 种子 | 0、1、2 |
| 评测指标 | 答案的 NLL（越低越好），按 episode 配对比较 |

为什么去掉超过 3000 token 的 episode：训练时显存不够（4000 token 时在第 127 步 OOM）。这是协议修订，在 `docs/design_G1e.md` §11 中已登记。代价是排除约 6% 的训练数据。

## 3. 判据（运行前登记，不得根据结果修改）

- **G1e-a**：K4_CL 减去 K1 的 NLL 差，95% 区间上界 < 0 → 分库优于单库。
- **G1e-b**：K4_CL 减去 K4_random 的 NLL 差，95% 区间上界 < 0 → 学习的分法优于随机分法。
- **G1e-c**：每个种子中，K4_CL 的最大库占比 ≤ 0.6 → 分库没有集中到一个库。

三条都满足才算通过。

## 4. 结果（截至记录时）

### 4.1 验证 NLL 曲线（每个运行，测试集前 100 行）

| 运行 | 第 0 步（未训练） | 第 100 步 | 第 200 步 | 第 300 步（最终） | 状态 |
|---|---|---|---|---|---|
| K1_full_s0 | 11.06 | 3.54 | 3.01 | **2.90** | 完成 |
| K4_CL_cons_s0 | 10.83 | 3.52 | 2.92 | **2.87** | 完成 |
| K4_random_s0 | 10.36 | 3.33 | 3.07 | 进行中（第 209 步） | 进行中 |

> 注：
> - 第 0 步的数值不同，是因为三个臂未训练时的起点就不同（读出的随机初始状态与结构有关）。比较时应看训练后的最终值，并同时报告起点。
> - 目前只有种子 0 的结果，单个种子的差异不能下结论。

### 4.2 训练后的库负载（G1e-c 的依据）

| 运行 | 四个库的占比 | 最大库占比 | 是否 ≤ 0.6 |
|---|---|---|---|
| K4_CL_cons_s0 | 0.23 / 0.27 / 0.22 / 0.27 | 0.27 | ✅ |

> 注：这是训练后的真实键上的占比，不是准备阶段的数值。负载均衡，没有集中到一个库。

### 4.3 训练稳定性

- 三个运行的梯度范数都没有出现 NaN。
- K4_CL_cons_s0 的梯度在训练中曾出现一次 4512 的尖峰，之后回落到 10 左右，整个运行没有超过 10⁴ 的步。
- 显存峰值约 27–28 GB，没有 OOM。

## 5. 目前能说什么，不能说什么

**能说的**：
- 三个运行都能稳定训练到 300 步，没有数值问题。
- 训练后的 K4_CL 负载均衡，符合 G1e-c。
- 在种子 0 上，K4_CL 的最终验证 NLL（2.867）略低于单库（2.895）。

**不能说的**：
- 不能说"分库有收益"。差值只有约 0.03，只有一个种子，还没有计算每个 episode 的配对区间。
- 不能说 K4_CL 优于 K4_random。随机臂还没有完成。
- 不能拿这些结果和之前的 E013 或 E024 直接比较，因为读出形式（修正版）与训练集（3000 token 上限）都不同。
