## 1. 上次汇报之后的时间线

### 1.1 E025（G1e）完成：分库训练检验未通过（N16）

- **动机**：上周的未决项。G1d 只测了路由，读出没有训练，因此"分库无收益"可能只是读出没学会利用分库。
- **做法**：3 个臂（K1 单库、K4_CL 竞争学习原型、K4_random 随机中心），等总状态、等可训练参数（125,884,416）、等预算（300 步，lr 1e-4），种子 0/1/2，读出分母 `abs`，训练集上限 3000 token。
- **结果**（测试 NLL，3 种子均值）：

| 比较 | 点估计 | 95% 区间 | 判定 |
|---|---|---|---|
| G1e-a：K4_CL − K1 | +0.014 | [−0.111, +0.137] | ❌ 未通过 |
| G1e-b：K4_CL − K4_random | −0.035 | [−0.133, +0.063] | ❌ 未通过 |
| G1e-c：最大库占比 | 0.27–0.28（K4_CL） | 判据 ≤ 0.6 | ✅ 通过 |

- **解读**：在本协议下，没有检出分库的组织收益。区间宽度约 ±0.12，远大于要检出的效应（约 0.03），统计功效不足。因此只能说"在该预算下没有可检出的收益"，不能说"分库无效"。
- **处理**：按总纲规则，不进入后续组合检验。

### 1.2 N15 更新：三个 K4_CL 种子是同一划分（修正）

- **发现**：`abs` 原型在三个种子间只差库编号的排列（去掉排列后差异约 10⁻⁷；未排列时差异 0.1–0.3）。E027 用匹配余弦复核：三个种子的匹配余弦为 1.000。
- **影响**：E025 的"三种子平均"对 K4_CL 不是独立重复。K4_CL 的区间只反映训练与测试样本的抽样变异，不反映分库的随机性。
- **修正**：上周的汇报写的是"三个种子"，实际上只有一个独立的分库样本。之后的分库检验需要显式报告"独立划分的数量"。
- ✅ 这一修正不改变 G1e 的判定，但降低了我们对 K4_CL 稳健性的信心。

### 1.3 E026（G2c）：分库 + 快照删除的组合——口径问题

- **动机**：分库与删除的组合是否冲突。
- **结果**：
  - G2c-a（删除精确）：✅ 通过，误差 0.0。
  - G2c-c（负载）：✅ 通过，K4 的最大库占比 0.29–0.33。
  - **G2c-b（删除不误伤）：❌ 按预先登记的口径未通过。** D = −0.064（K1）与 −0.080（K4），区间全部低于 −0.01。注意：K1（单库）也有同样的下降，说明它不是分库造成的。
- **第二次登记**：在看到探索性诊断之后，我们提出一个新口径（按实际写入的键评估，去掉闭环键变化的影响）。在该口径下，删除没有可检出的误伤（变化在 ±0.01 以内）。
- **诚实的说明**：第二次口径是在看到结果后提出的，是对测量的修正，**不替代**第一次登记的 G2c-b 结论。因此：
  - ⚠️ 结论只能表述为"在修正口径与单一划分下，组合没有显示冲突"。
  - 旧口径的大幅下降被诊断为闭环键变化造成的测量假象（key_shift 为 0.027），这一解释有证据支持，但不是预先登记的结论。

## 附录 A：具体例子（公式与中间数值）

本附录给出每个关键结论的计算过程。A1、A2 是小规模的手算例子，由 `src/holistic/rls_metis.py` 的实际函数复算验证；A3–A6 使用实验结果文件中的真实数字。

### A1. RLS 一次 chunk 提交（d = 2，λ = 0.9，两个 token）

**公式**（信息形式，块提交，对应 `rls_commit_update`）：

  Λ_t = λ Λ_{t−1} + Σ_i w_i κ_i κ_iᵀ，　b_t = λ b_{t−1} + Σ_i w_i κ_i v_iᵀ，　M_t = Λ_t⁻¹ b_t，　P_t = Λ_t⁻¹，　z_t = λ z_{t−1} + Σ_i w_i κ_i

键按模型的尺度缩放：κ = kn / √kv（这里 kv = d = 2）。先验 P_0 = kv·I = 2I，即 Λ_0 = 0.5 I。

**输入**：kn_1 = (1, 0)，kn_2 = (0.6, 0.8)；v_1 = (2, 1)，v_2 = (0, 3)；w = (1, 1)。

**中间过程**：

| 量 | 计算 | 数值 |
|---|---|---|
| κ_1 | (1, 0)/√2 | (0.7071, 0) |
| κ_2 | (0.6, 0.8)/√2 | (0.4243, 0.5657) |
| λΛ_0 | 0.9 × 0.5 I | 0.45 I |
| κ_1κ_1ᵀ | | [[0.50, 0], [0, 0]] |
| κ_2κ_2ᵀ | | [[0.18, 0.24], [0.24, 0.32]] |
| Λ_1 | 0.45 I + 两项之和 | [[1.13, 0.24], [0.24, 0.77]] |
| b_1 | Σ κ_i v_iᵀ（λb_0 = 0） | [[1.4142, 1.9799], [0, 1.6971]] |
| det Λ_1 | 1.13 × 0.77 − 0.24² | 0.8125 |
| P_1 = Λ_1⁻¹ | (1/0.8125)·[[0.77, −0.24], [−0.24, 1.13]] | [[0.9477, −0.2954], [−0.2954, 1.3908]] |
| M_1 = P_1 b_1 | | [[1.3402, 1.3751], [−0.4177, 1.7754]] |
| z_1 | Σ κ_i | (1.1314, 0.5657) |

**解读**：M_1 的第一行第一列 1.3402 = (0.77 × 1.4142) / 0.8125，这是手算的检查点。这个例子说明：每个 chunk 写入的 M 是对所有键的一次联合最小二乘解，而不是逐条叠加。

**与 p_max 的关系**：当某方向未被激励时，Λ 的特征值接近 λ 衰减后的值，P 会增大（windup）。p_max 限制 P 的最大特征值，以防止这一点（N8、N9）。

### A2. 读出分母：一个负分母如何放大梯度

**公式**：原版读出 y = qM / (q·z + 1)（`orig`）；修正版 y = qM / (1 + |q·z|)（`abs`）。

**数值**：设某次读出 q·z = −1.02。

| 分母 | 计算 | 值 | 读出增益 1/|den| |
|---|---|---|---|
| orig | −1.02 + 1 | −0.02 | 50.0 |
| abs | 1 + |−1.02| | 2.02 | 0.495 |

同一个 qM，`orig` 的读出放大约 100 倍（50 ÷ 0.495）。读出对 M 的梯度为 q/den，因此梯度的放大倍数近似相同。这与 E025 的实测一致：在同一批 episode 上，`orig` 的梯度最高达 1.3×10⁵，`abs` 为 4.4×10³（上周汇报 §6.2）。

**为什么只在少数读出中出现**：q·z 接近 −1 的读出很少（0.6–6.7%），但每一次都可能产生 10⁵ 量级的幅值，因此最大值被这些少数读出主导。

### A3. 残差值解码（E030，第 3 层的真实数字）

**公式**：

- 存储：r_t = v_t − M_v κ_{t−1}（M_v 为 fit 划分上的岭回归，κ_{t−1} 为前驱键）。
- 解码（b1）：v̂_t = a · (κ_t M_r) + b · M_v (B κ_t)，其中 B 为 κ_t → κ_{t−1} 的岭回归，a、b 为 fit 划分上的最小二乘系数。
- 误差：e_t = ‖v̂_t − v_t‖ / ‖v_t‖，报告 tune 划分上的中位数。

**第 3 层的拟合系数**（fit 划分）：

| 变体 | 系数 | 中位误差 e |
|---|---|---|
| b0（纯存储） | a = 0.0335 | 0.2802 |
| b1（残差 + 补偿） | a = 0.0384，b = 0.9824 | 0.2909 |
| b1-naive（无补偿） | a = 0.0569 | 0.8765 |
| b2（存前驱键，2 倍状态） | a = 0.0404，b = 0.0318 | 0.2785 |
| 补偿误差 ‖M_v(κ_{t−1} − Bκ_t)‖/‖v_t‖ | | 0.2817 |

**解读**：

- b1 的补偿系数 b = 0.98，接近 1，说明补偿项按预期的倍数使用，没有被最小二乘压低。
- b1-naive 的误差 0.88，远高于 b0 的 0.28，说明无补偿时残差存储不能还原 v。
- 误差 0.29 与 b0 的 0.28 只差 0.011，这是采用 b1 的依据。
- a 很小（约 0.03–0.06），反映载体读出的整体缩放（未深入核对），它不影响比较，因为每个变体都单独拟合。

**小样本的反转**：3 个 episode 的试跑中，第 3 层 b1 为 0.605、b0 为 0.277（b1 明显更差）。全量 135 个 episode 上，b1 为 0.291、b0 为 0.280。这说明小样本的中位数不可靠。

### A4. 快照重放删除（E020，精确删除的具体流程）

**流程**：一个会话有 5 个 chunk，要删除第 2 个。

1. 取第 2 个 chunk 之前保存的快照 S_1（即 chunk 1 之后的状态）。
2. 从 S_1 恢复状态。
3. 依次重放 chunk 3、4、5（它们的键需要按新的状态重新计算）。
4. 得到的状态与"从未写入 chunk 2"的参考状态逐位比较。

**数值**：状态误差 0.0（所有 episode）；平均重放 3.1 个 chunk（会话平均 5 个）。平均重放数小于 5，是因为被删 chunk 之后的 chunk 数随位置变化。

**对照（降秩删除）**：同样的删除用降秩（减去被删 chunk 的贡献）时，较早 chunk 的误差为 1.38、1.05、10¹⁴、0.64、0.0（N14）。误差 10¹⁴ 说明数值会爆炸，降秩不能作为删除机制。

### A5. E029 的配对差（真实数字）

d_i = NLL_GDN,i − NLL_P0,i。前三个 episode：

| episode（尾部） | GDN | P0（RLS 基线） | d_i |
|---|---|---|---|
| conv-43 … 1-6-11 qa_0000 | 3.2031 | 3.8906 | −0.6875 |
| conv-43 … 6-11 qa_0001 | 3.1406 | 4.2188 | −1.0781 |
| conv-43 … 1-12-27 qa_0002 | 3.7344 | 5.2812 | −1.5469 |

这三个的均值为 −1.1042。全部 100 个 episode 的均值为 −0.345，bootstrap 95% 区间为 [−0.523, −0.155]。

**bootstrap 的过程**：从 100 个 d_i 中有放回抽样 100 次，计算每次的均值；取 5000 次均值的第 2.5% 与 97.5% 分位数作为区间（实际计算中使用 5000 次重抽样）。

### A6. E025 的单个 episode 噪声（为什么区间很宽）

种子 0 的 K4_CL − K1 在 100 个 episode 上：

- 前三个 d_i：−0.4766、−0.1953、+0.0312。
- 全部均值：−0.0284；标准差 0.822；标准误 0.822 / √100 = 0.082。

**解读**：单个 episode 的差值标准差（0.82）远大于要检出的效应（约 0.03）。因此 3 个种子平均后的区间宽度（约 ±0.12）大致只能检出 0.2–0.25 nats 量级的效应（粗略估计，未做功效分析）。这与 N16 的"统计功效不足"一致，也解释了为什么"无收益"的结论不能过度解释。

### A7. E031 的比值与 NLL 的对应

- 第 3 层的记忆 / 注意力范数比：GDN 29.12，RLS 37.58，比值 37.58 / 29.12 = 1.29。
- 无记忆地板 6.052。GDN 高出 7.283 − 6.052 = 1.23 nats；RLS 高出 9.434 − 6.052 = 3.38 nats。

**解读**：RLS 的记忆分支更大（1.29 倍），但 NLL 的增加却是 GDN 的 2.7 倍（3.38 / 1.23）。因此"分支幅度"不能单独解释两者差距，它只能解释一部分。这一点与上文"RLS 的差距主要来自分支幅度"只是猜想相一致。
