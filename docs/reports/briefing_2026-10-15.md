# Metis 记忆结构的控制论改造：阶段性进展汇报

日期：2026-10-15　　用途：对外汇报（不作为项目推进文件）
数据状态：截至本文件撰写时。阶段 1b 的对照训练仍在进行，相关结论标注为"待定"。

---

## 一、动机

Metis 的记忆是每层一个线性矩阵 $M$（加键的累计状态 $z$），所有信息叠加在同一状态里。我们关心三类问题：

- **衰减**：信息随时间变弱；
- **串扰**：不同信息互相干扰；
- **删除误伤**：删除一条信息时影响其他信息。

我们的判断是：问题不只在"线性"本身，而在于**多个线性单元之上缺少组织层**。控制论提供了一套可以直接描述这一问题的语言：

| 控制论概念 | 对应的记忆问题 |
|---|---|
| 线性时变 / 参数线性变化（LPV）系统 | 状态线性，系数依赖输入 |
| 时间常数、极点 | 遗忘速度，多时间尺度 |
| 切换系统、切换律 | 分库与路由 |
| 卡尔曼增益、RLS | 写入强度应依赖不确定性 |
| 寻址投影 | 有地址的删除 |
| 解耦、可观测性格拉姆矩阵 | 串扰与容量 |
| Koopman 提升 | 非线性输入的线性表示（用户指定的探索方向） |

目标是**整体改造**记忆架构，而不是对某个机制打补丁。约束是：状态递推对记忆状态保持线性，非线性只放在路由、增益、输入特征映射和读出归一化中。

## 二、路线的演变

1. **最初**：先做局部诊断，区分衰减、串扰、删除误伤三类问题（E001）。
2. **转向**：用户指出目标是整体改造，而不是找单个突破点。我们因此把 CLAUDE.md 的方向限制放宽，改为以 `ideas_Cybernetics.md` 为依据。
3. **原则**：经典控制理论已经解析给出的规则（增益、极点、降秩、稳定性界）不交给学习；只有路由中心需要学习。
4. **流程**：结构性改动先写设计说明，获确认后再编码。

## 三、对真实 Metis 的诊断（已验证）

在 Metis-4B 上测量训练后的写入门控与读出贡献。

**门控分布（E002 合成数据，E003 LoCoMo 写入路径）**

- 遗忘强度随层变化很大：前层（第 3 层）每次写入平均保留约 12%–26%，中后层（第 31 层）保留约 71%–90%。
- 按键擦除的强度远小于遗忘：擦除与遗忘之比约为 $10^{-5}$–$10^{-3}$。

**读出贡献（E004，100 个会话，247 个问题，答案 token 的 NLL 配对差）**

| 消融 | 差值 | 95% 区间 |
|---|---|---|
| 去掉遗忘（α=1） | +0.43 | [+0.32, +0.56] |
| 去掉按键擦除 | +0.0005 | [−0.003, +0.004] |
| 不用记忆 | +2.11 | [+1.83, +2.42] |

**擦除的稳健性（E005，fp32 对照与多子集复核）**

- 状态精度从 bf16 提到 fp32，对结果的影响可以忽略（差值 +0.002，区间包含 0）。
- 三个会话子集上，去掉擦除的差值分别为 −0.004（区间不含 0）、+0.0003、−0.0003；合并估计 −0.002，区间 [−0.005, +0.001] 包含 0。
- 结论：按键擦除对读出的贡献在 ±0.005 nat/token 以内，远小于遗忘的贡献。
- 注意：第一个子集单独看有边缘显著的负效应，但其他子集没有复现，因此不能作为结论。

**阶段性结论（已验证）**：Metis 依赖遗忘，但基本不依赖按键擦除。按键擦除在现有形式下没有价值。

## 四、参考模型上的机制验证（0a）

用参考线性记忆（64 维，无训练参数）验证各个机制的理论预期。

**E001：三类问题的基本形式（合成）**

- 衰减：有效时间常数与理论值 $-1/\ln\lambda$ 一致（这是实现检查）。
- 串扰：随相关性 $\rho$ 线性增长，随干扰数增加到饱和。
- 删除误伤：按键投影删除的误伤随 $\rho$ 增大，全局缩放没有选择性。

**E006：分库与路由（GDN 形式）——多数设计假设被推翻**

- N1：等参数分库用随机投影压缩键，破坏了键的正交性。即使理论上 $\rho=0$，召回也只有约 0.04–0.08（基线 1.00）。
- N2：软路由在未训练的中心下几乎均匀，分库没有发生。
- N3：软路由下删除不完整，目标残留 0.80–0.99。
- N4：相关键导致路由塌缩（最大库利用率从 0.30 升到 0.59）。
- N5：未训练路由下，快慢两库不优于单库。
- 有一个正面证据：分库加 top-1 路由在 $n=32$、$\rho=0.3$ 时，召回从 $-0.01$ 提到 $0.27$。

**E007：RLS 增益（协方差解析给出）——明显优于 GDN**

- 召回：$\rho=0.3$、$n=32$ 时，从 $-0.01$ 提到 $0.67$；$n=128$ 时，从 $0.10$ 提到 $0.25$。
- 年龄曲线：$\alpha=0.999$、年龄 256 时，从 $0.14$ 提到 $0.44$。
- 删除：带遗忘权重的降秩删除（权重为 $\lambda^{\text{age}}$）精确，残留与误伤均为浮点舍入量级（单元测试与 E007 验证）。

**E008：等状态对照——RLS 的优势不来自多存的协方差**

- 等状态（$2\cdot64^2$）的 GDN 两库对照中，RLS 仍明显更好（$\rho=0.3$、$n=128$：RLS $0.40$，GDN $0.05$–$0.06$）。
- 分块投影（坐标分块）与随机投影没有差异（E008b），因此 N1 的根本原因是等参数分库破坏了目标与干扰的正交结构，不取决于投影形式。
- 决定：分库默认关闭，仅作为满维度键的可选项（代价为 $K$ 倍状态）。

**E012：块形式的 RLS 更新（精确）**

- 信息形式下 RLS 是线性的，一个 chunk 的闭式更新与逐 token 更新数值等价（float64 下误差约 $10^{-12}$）。
- 在 Metis 维度（1024，单层，512 token）下，速度从 0.35 秒降到 0.006 秒，约 60 倍。

**阶段性结论（已验证，合成数据）**：在参考模型上，RLS 解析增益在召回、年龄曲线、删除上都优于 GDN 形式；分库在等参数下不成立；块形式可以高效且精确地计算。

## 五、接入 Metis 与训练可行性（1a）

**接入**：RLS 作为可替换的记忆模块接入 Metis 的 local_memory，不修改 `metis/` 中的代码，只在实验中替换方法；卸载后可恢复原始行为。

**可行性（E011，随机 token，只测可行性）**

- 冻结骨干后，可训练参数约 1.26 亿，占总量的 2.5%。
- 显存随 chunk 数线性增长，每个 512 token 的 chunk 约增加 2.3 GiB。8 个 chunk 时峰值约 29 GiB，接近 32 GB 显存上限。
- 梯度检查点与记忆写入的副作用不兼容（反向重算的元数据不一致），因此单卡 episode 长度上限约为 8 个 chunk。**这一限制已由用户接受，前提是能对比出效果。**

**约束**：查询前至少需要两次写入，否则 α 门控的梯度恒为零（E011 中的 2-chunk 实验显示 16 个 α 张量梯度为零，3 个以上 chunk 时全部有梯度）。

## 六、阶段 1b：原版与 RLS 的对照训练（进行中）

**设计**（`docs/design_1b.md`，已确认）

- 数据：合成记忆任务（实体属性事实、更新、干扰句、查询）。训练与验证使用不重叠的实体和取值。**不使用任何评测数据训练。**
- 两个变体都从头初始化记忆参数（骨干冻结）：原版（GDN 形式，门控可学习），RLS（解析增益，去掉门控参数）。
- 3 个种子，每次 300 步、梯度累积 4（共 1200 个 episode），学习率 $10^{-4}$，验证集 200 条。
- 判定规则事先约定：配对 bootstrap 区间不含 0 且为负，才认为 RLS 更好；包含 0 为无差异；明显更差则记为负结果。

**当前状态**：6 个训练任务在后台顺序运行，预计约 3 小时。结果出来后再给出结论。

**已知的解读风险**

- 基线从头训练远弱于原版预训练记忆（诊断：无记忆 10.5，预训练 GDN 记忆 5.4，从头训练的基线需要长得多的训练才能接近）。因此即使 RLS 比从头训练的基线好，也不能说明它优于原版预训练的 Metis。
- 合成任务与真实评测不同，结论不能直接外推。
- 训练步数只有 300，较短。
- RLS 的遗忘因子 $\lambda=0.9$（每个 commit 衰减一次）固定，没有调参。

## 七、过程中发现并修正的问题

这一部分记录开发过程中的错误和修正，便于判断结论的可靠性。

1. **静默清零的接口缺陷**：批量大小不一致时，`read` 会把记忆清零。E006 的第一轮 M3 因此全部为 0。已改为报错，并记录在负结果中。
2. **直通估计写错**：top-1 时对单个选中项做 softmax，结果恒为 1，梯度为 0。已改为对全部库做 softmax。
3. **浮点精度**：`alpha` 以 float32 存储，经 `.double()` 后仍有约 $2\times10^{-8}$ 的误差，会随步数累积。已改为 float64。
4. **解耦损失的坐标依赖**：非对角损失依赖坐标基，不是不变量。已改为格拉姆矩阵特征值的对数离散度，并加旋转不变性测试。
5. **删除指标的定义变化**：E006 用删除前后的变化量，E007 改为与"从未写入目标"的参考比较。两者不能直接比较。
6. **λ<1 时降秩不精确（N6）**：信息形式下，条目的权重是 $\lambda^{\text{age}}$，降秩必须用这个权重。已修正，并以单元测试验证。
7. **RLS 训练崩溃**：单位键下读出分母 $q^\top z+1$ 接近 0，梯度达到 $10^5$–$10^6$。改用 Metis 的键尺度 $\kappa/\sqrt{kv}$ 并把先验设为 $kv\cdot I$，两者等价（余弦 1.0）。修正后可以训练。
8. **基线不公平**：最初两个变体都用预训练的记忆参数，与设计不一致。已改为两者都从头初始化，并在报告中说明。
9. **E011 的 α 梯度为零**：并非代码错误，而是 episode 太短（查询前只有一次写入）。已在数据设计中满足两次以上写入的条件。
10. **梯度检查点不兼容**：反向重算与记忆写入副作用冲突。目前以 8 个 chunk 为上限，已由用户接受。
11. **环境问题**：PyPI 官方源和 GitHub 无法直接访问，依赖通过清华源安装；环境变量中的本地代理在部分时间不可用，安装时需要去掉代理变量。Triton 版本为 3.1.0，低于推荐的 3.2.0，目前未出现错误。

## 八、主要风险与未决问题

- **真实键分布**：所有分库与路由的实验都用合成键。分库和学习路由的收益只能在真实的记忆键分布上验证（需要阶段 1 的真实训练数据）。
- **评测数据**：MetisTest、MetisOps 等数据不可得，只能使用 LoCoMo。LoCoMo 目前只用于诊断（E002–E005），没有用于训练。完整的 MemOP 评测无法复现。
- **训练数据**：合成数据与真实任务的分布差异可能很大。真实训练数据到位后需要重新训练。
- **长 episode**：单卡 8 个 chunk 的上限限制了可训练的会话长度。
- **λ 与多时间尺度**：RLS 的遗忘因子固定，多时间尺度（快慢两组）尚未在有训练的设置下验证。
