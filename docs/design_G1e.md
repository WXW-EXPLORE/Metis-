# 设计 G1e：训练后的读出下，等状态分库是否优于单库（真实对话）

状态：**草案，待用户确认后编码**（CLAUDE.md：结构改动先设计、获确认后再编码）。
日期：2026-10-17。依据：用户决定"若无暴雷影响则暂时接受 G1d 的失败并继续推进"。
前置：N15（G1d 未通过）、E013（从头训练，300 步，未分辨）、H16、H10b。

---

## 1. 要检验的假设

**H17（新，预先登记）**：在等总状态、等可训练参数、等训练预算下，数据自适应分库（K=4，竞争学习原型，内稳态，β=1）训练后的验证 NLL 优于单库（K=1），且优于内容无关的分配（K=4，随机固定中心）。

来源：用户提出的解释。G1d 只测了路由本身（读出未训练），因此"分库无收益"可能只是读出没有学会利用分库。G1e 直接检验这一点。

**与 G1d 的关系**：G1d 是零训练的离线检验，G1e 是训练检验。两者并不互相"救"：G1d 的失败结论保持不变（N15），G1e 是独立的新门控，判据在运行前登记。

## 2. 对照臂（单变量：只改分库结构）

| 臂 | 状态 | 路由 | 训练参数 |
|---|---|---|---|
| K1_full | 1024×1024 | 无 | 与其他臂相同的读写参数 |
| K4_CL | 4×(256×1024) | 竞争学习原型（β=1）由训练数据决定，之后固定 | 同上 |
| K4_rand | 4×(256×1024) | 固定随机中心（同 E022 的抽取方式） | 同上 |

- 等状态：K4 每库状态为 256 行，总状态与 K1 相同。
- 等参数：三臂的可训练参数量相同（路由原型不计入可训练参数，原型由数据确定，见 §3）。
- 读写参数、记忆层位置（层 3 与层 7，与 G1d 相同）、学习率与步数、优化器全部相同。

**新增设计选择（需确认）**：路由原型用 G1d 的竞争学习在 fit 集上得到，训练时固定。否则路由是可训练参数，会改变"等参数"的含义，并引入额外自由度。

## 3. 数据与拆分

- 真实对话：LoCoMo 记忆步骤（同 E024），fit 5 个对话，test 5 个对话（按对话拆分，不泄露）。
- 训练：在 fit 对话上以答案 NLL 训练（骨干冻结，记忆参数从头初始化，与 E013 一致）。
- 评测：test 对话的答案 NLL，每个 episode 保存，用于配对 bootstrap。
- 不修改评测集、指标或划分（CLAUDE.md）。

## 4. 训练预算与种子

- 步数与学习率：先固定为 E013 的设置（300 步，lr 1e-4，梯度累积 4）。**此设置可能不足以收敛**，这一点要在结果中报告；若为了收敛而改预算，必须在运行前重新登记，并对三个臂一起改。
- 种子：3 个（训练种子同时决定 K4_CL 的原型初始化与 K4_rand 的中心）。
- 报告：每臂的均值与标准差、每个种子的值、每个种子的负载向量（不取平均）、路由熵与最大库占比。

## 5. 判据（运行前登记）

主比较：K4_CL − K1_full，test 答案 NLL 的配对差（按 episode 配对，bootstrap 95% 区间，3 个种子的平均）。

- **G1e-a（主判据，通过）**：区间上界 < 0，即 K4_CL 的 NLL 显著低于 K1。
- **G1e-b（分库是否优于内容无关分配）**：K4_CL − K4_rand 的区间上界 < 0。
- **G1e-c（负载，必须同时满足）**：K4_CL 每个种子的最大库占比 ≤ 0.6，否则判为负载集中，G1e-a 的结论只能标注为"可能来自有效库变大"，不计为通过。

**通过**：G1e-a 与 G1e-b 同时成立，且 G1e-c 满足。
**未通过**：任一条件不成立。
**不可判定**：训练出现 NaN、梯度爆炸或状态发散（按 CLAUDE.md 停止，定位原因，不以此调参）。

## 6. 失效模式与风险

- **训练未收敛**：300 步可能不足。这会使所有臂的结果都偏向"随机初始化"，因此主判据同时要求各臂的训练损失下降（报告 init 与 final）。若各臂都几乎未下降，结论为不可判定。
- **负载塌缩**：原型在 fit 集上可能收敛到单库。由 G1e-c 直接检出。
- **K4_CL 与 K4_rand 的差异可能很小**：与 G1d 相同的风险。此时 G1e-b 不成立，结论是"内容路由无可检出的组织收益"。
- **与预训练记忆的差距**：E013 显示从头训练的记忆远弱于预训练 GDN（5.8 vs 5.4）。G1e 只比较从头训练的各臂，不与预训练模型比较。

## 7. 回退

- 实验全部通过替换方法（monkeypatch）完成，不修改 `metis/` 下的代码；卸载后用回归测试确认原版行为（沿用 G2b-0 的做法）。
- 新机制通过开关启用，默认关闭。
- 失败的运行保存在 `invalid_*` 目录并附说明，不作为结论。

## 8. 与其他分支的关系

- 若 G1e 通过：H16 从"仅合成键"升为"真实键、训练后"的 ⚠️，之后再考虑多中心抽取的负载稳健性（E022 的问题）。
- 若 G1e 未通过：确认分库在真实对话上无可检出收益，主线的组织方向转向 H11 或 H13 的前提需要重新评估，由用户决定。
- 不影响 G2、G2b 的构造性结论。

## 9. 需要用户确认的点

1. 路由原型用 fit 集的竞争学习得到并在训练时固定（而不是可训练）。
2. 预算先沿用 E013 的 300 步，若不收敛是否允许在登记后统一加长。
3. G1e-c 的负载阈值 0.6（借鉴 E022 中 7/10 抽取超过一半的观察，取较宽的上限）。

## 10. 运行前修订（2026-10-19，确认后、运行前登记）

依据：E025 诊断（`experiments/E025_G1e_train/diag_mech_pair_*`、`diag_mech_abs/`）与 12 步训练试验（`/hy-tmp/e025_trial_abs12`）。
判据 G1e-a/b/c **不变**。以下两项是协议修订：

1. **读出分母改为 `1 + |q·z|`（`abs`）**，设计见 `docs/design_readout_norm.md`。
   - 原因：`orig` 分母 `1 + q·z` 在约 1–7% 的读出中为负，梯度最大达 10⁵ 量级。
   - 证据：预先登记 R1 在固定种子下通过（最大梯度 5.8×10³，最大读出幅值 72；`orig` 为 1.3×10⁵ 与 8.4×10⁵）。12 步训练中梯度稳定在 456–2128。
   - 影响：`orig` 下的 E013、E025 结果不能与本次结果直接比较。本次全部臂（K1_full、K4_CL_cons、K4_random）统一使用 `abs`。
2. **训练集剔除超过 4000 token 的 episode**（仅训练集；评测集与划分不变）。
   - 原因：`orig` 与 `abs` 的 12 步试验都在第 12 步因显存不足（CUDA OOM）失败，位置相同，与读出无关。峰值显存随 token 数增长（约每 token 4 MB，加上约 13 GB 基线）。
   - 影响：fit 训练行由 756 减到 737（剔除 19 行，约 2.5%）。
3. **原型的准备步骤（prep）同样使用 `abs` 读出重新计算**，使 K4 的路由中心与训练时的键分布一致。`orig` 版本的 `prototypes.pt` 保留，不用于本次。
4. **运行目录**：本次结果写入 `experiments/E025_G1e_train/runs_abs/`，与之前的 `runs/` 分开。

**不变的部分**：臂的定义、等状态与等参数、300 步、学习率 1e-4、种子 0/1/2、测试集前 100 行、判据 G1e-a（K4_CL − K1 的 95% 区间上界 < 0）、G1e-b（K4_CL − K4_random 的 95% 区间上界 < 0）、G1e-c（每个种子的最大库占比 ≤ 0.6，按训练后的真实键计算）。

**需要注意的局限**：4000 token 上限会改变训练数据的分布，结论只适用于"长度 ≤ 4000 token 的训练集"。这一点在报告中必须说明。

## 11. 再次运行前修订（2026-10-19，确认后登记）

依据：修订版（§10）的第一个运行 K1_full_s0 在第 127 步因显存不足失败；episode 长度在 4000 token 以内。
显存诊断（`experiments/E025_G1e_train/diag_chunks/result.json`，只前向反向，实测）：峰值 ≈ 9.8 GB + 4.8 MB/token + 0.12 GB/chunk（残差 0.14 GB）。3000 token、4 chunk 实测峰值 24.7 GB；推算 4000 token 约 29.4 GB，加 fla 工作空间后超过 31.5 GB 上限。

修订：

1. **训练集上限由 4000 改为 3000 token**（仅训练集，评测集与划分不变）。3000 以上的训练行约 44 行（5.8%），fit 行由 756 减为约 712。
2. **答案统一为字符串**（§10 之后的数据格式修复）：6 行的答案为整数（如 2022），训练中会因 tokenizer 报错。转为字符串只改变表示，不改变答案内容。
3. 判据 G1e-a/b/c、臂、种子、步数、学习率、readout abs、原型（`abs/prototypes.pt`）均不变。

结果归档：4000 上限下的失败运行移至 `runs_abs_invalid_cap4000/`，不作为结论使用，也不与新结果混合。

局限（须在报告中说明）：结论只适用于长度不超过 3000 token 的训练集，长 episode 被排除。
