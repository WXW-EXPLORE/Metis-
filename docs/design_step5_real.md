# 设计草案：第 5 步 — 真实模型键上的外部检验（待确认）

日期：2026-10-22。状态：**草案，待确认后运行**。

## 1. 要检验什么
学到的观测层预测器，在真实 Metis 键上能否跨对话泛化（K-A 的真实数据版本）。真实数据没有已知的潜在结构，因此**不做** K-C（干预）与 K-B（不变性）。

## 2. 数据
- E028 录制的真实写入键（`/hy-tmp/e028_keys.pt`，8 层全部保存，开环 RLS 录制）。
- 划分沿用 E028：fit = 前 3 个对话（138 个 episode），tune = 第 4–5 个对话，test = 第 6–10 个对话（295 个 episode）。
- 序列：每个 episode 内按 chunk 顺序的键均值（每个 chunk 一个向量），构成 chunk 级序列；维度 1024 经 PCA（fit 拟合）降到 d=8 或 32（待定）。

## 3. 臂与指标
- **P_learn**：在 fit 的 chunk 序列上学习一步线性预测器 M（LMS，与 R1b 相同的步长调度）。
- **P_base**：零预测；**P_marg**：只用 fit 的均值预测（无时间信息）。
- 指标：test 上一步预测的 NMSE；配对 bootstrap（按 episode）。

## 4. 判据（草案，阈值待低成本预试验确定）
- **S5-a**：P_learn 的 NMSE 显著低于 P_base（区间下界 > 0）。这是真实键上存在可预测的时间结构的证据。
- **S5-b**：P_learn 的 NMSE 显著低于 P_marg（区间下界 > 0）。这排除"只靠均值"的解释。
- 阈值与 PCA 维度 d 由预试验（fit/tune 划分上）选定，不在 test 上调。

## 5. 局限（须在报告中说明）
- 键是开环录制（与 G1 相同），闭环中键会随记忆改变（N10）。
- 对话之间的时间结构可能弱；若 S5-a 不成立，结论是"真实键的 chunk 级时间结构不足以支持预测"，不是方法失败。
- 测试集已在 E028 的 G4 中使用过（按 E028 划分）。本步的测试结论需注明这一点，或改用新划分。

## 6. 需要确认的决定
1. 使用 E028 的划分（测试集重复使用），还是只用 fit/tune 做预试验与判定（需要新的留出）。
2. chunk 级序列的构造（键均值）是否可接受，还是使用逐 token 序列。
3. 阈值与 PCA 维度由预试验确定（同意的话，我先做低成本预试验，不占测试集）。

## 结果（2026-10-22，test，E028 划分，295 个 episode）

- 预试验选定：token 逐个序列，PCA d=8（`experiments/step5_real/pilot.json`，只用 fit/tune）。
- 层 3：零预测 1.000，均值基线 1.000，学习预测器 0.606；S5-a 优势 0.394 [0.392, 0.396]；S5-b 0.394 [0.392, 0.396]。
- 层 7：零预测 1.000，均值基线 1.000，学习预测器 0.582；S5-a 优势 0.418 [0.415, 0.422]；S5-b 0.418 [0.415, 0.422]。
- **判定**：S5-a 通过，S5-b 通过。

**局限（必须注明）**：
- 测试集已在 E028（G4）中使用过，本结论沿用同一划分。
- 序列为 token 逐个，优势主要来自相邻 token 的局部相关性（同一 chunk 内相邻词的内容相关）。这说明真实键存在可预测的局部结构，**不能**作为"形成了可泛化知识"的证据。
- 没有做跨对话的泛化检验（预测器在 fit 对话上学习、在未见对话上测试是已做的，但预测目标是同一 chunk 内的下一个 token，非跨对话的知识）。
