## 0. 提议的新方向（2026-10-22，用户建议；未采纳，待讨论与确认）

> 本节是用户提出的建议，尚未采纳。在确认之前，§1–§7 仍是当前的推进链；本节不改变任何已登记的判据或已有结论。

### 0.1 总目标

研究经验如何自发转化为**稳定、可更新、可泛化**的内部知识表示。不预设这种表示必须是某种矩阵结构（如低维子空间或分库耦合）。

### 0.2 工程基础（保留，不推翻）

- 线性载体：RLS 块形式（E012）、特征值上界（N8、N9）、读出归一化修正 `abs`（`docs/design_readout_norm.md`）。
- 删除：快照重放精确（G2、G2b、G2c-a），降秩不作为删除机制（N10、N14）。
- 诊断与测试框架：梯度/显存诊断、单元测试、等参数与多种子报告。
- 组织组件（分库、快慢分组）：结论为"保留与组织有条件收益"（G1c、G4）或"未检出"（G1e、N16），作为候选组件，待知识形成检验后再组合。

### 0.3 待验证的假设（用户提出，不作为前提）

- **P1**：规律子空间 U 提取的共同特征可能只是统计相关，未必是规律。
- **P2**：U 随经验演化会使旧经历的编码与新子空间不一致，破坏准确性。
- **P3**：快库仅存残差，不保证经历可被准确检索和重建。
- **P4**：双时间尺度与线性/非线性分工本身不新颖，不能直接证明经验内化。

### 0.4 研究问题

- **RQ1**：规律如何从多次经历中逐渐形成，并区别于简单统计压缩？
- **RQ2**：组织结构持续演化时，如何保证旧记忆稳定，同时允许知识更新？
- **RQ3**：如何通过因果干预、跨情境泛化与原始经历屏蔽，证明系统形成了可迁移的知识，而非仅提高存储效率？

### 0.5 核心假设（H-K，待验证）

经验可以被压缩为可更新的内部表示，该表示能泛化到未见经历，并在因果干预与原始经历屏蔽下保持有效。

### 0.6 检验框架（替代以"自检索保留"为主要指标）

| 检验 | 内容 | 回应的问题 |
|---|---|---|
| A 泛化 | 对未见的同类经历，表示能否准确编码/重建 | RQ1，P1 |
| B 无规律对照 | 同样的统计结构（协方差）但无因果规则的数据：若收益相同，则是统计压缩而非规律 | P1 |
| C 因果干预 | 改变潜在因子，表示应相应改变（而不是仅随统计相关改变） | RQ3 |
| D 原始经历屏蔽 | 删除原始样本后，仍能回答同类问题 | RQ3，P3 |
| E 更新 | 新证据应修改旧知识，同时旧记忆保持稳定（可塑性–稳定性权衡） | RQ2，P2 |
| F 稳定性 | 大量无关经历之后，已形成的表示保持（有界漂移） | RQ2 |

### 0.7 阶段（按依赖顺序）

- **R0（已完成，合成数据）**：慢速规则在结构已知数据上形成子空间（T1、T2 通过）；学习率衰减加大数据量时稳定性通过（R0b，C4）。这只证明"慢速规则可形成子空间"，不证明规律。
- **R0c（待设计）**：P1 的检验。构造同一协方差、不同因果生成机制的数据（B 检验），判断子空间学习能否区分统计压缩与规律。
- **R1（待设计）**：P2 与 E 检验。规律形成后，引入新的规律（更新），检验能否学习而不破坏旧表示；可塑性–稳定性权衡的量化。
- **R2（待设计）**：P3 与 D 检验。快库的残差加编码能否重建原经历；屏蔽原始样本后能否回答同类问题。
- **R3（待设计）**：C 检验。因果干预（改变潜在因子）下表示是否相应改变。
- **R4**：真实模型键（LoCoMo）上的外部检验。真实规律未知，只能检验 A、E、F 的替代形式。
- **R5**：训练检验（需要训练预算与多种子），在 R0–R3 确立检验框架后进行。

### 0.8 约束与原则

- 线性单元作为载体保留；非线性组织机制（规律子空间、路由、编码）允许通过经验演化，须通过 A–F 判定（`CLAUDE.md` 2026-10-21 更新）。
- 不预先假定规律是低维子空间；子空间只是一个待检验的候选表示。
- 每个阶段先写设计说明并预先登记判据，获确认后再编码。
- 数据质量与数量会影响判据，因此数据规模与复杂度作为被检验的变量预先登记（R0b 的经验）。

## 1. 问题与目标

**问题**：Metis 的记忆是每层一个线性矩阵 $M$（加键的累计状态 $z$），所有信息叠加在同一状态。可能的问题：遗忘（衰减）、串扰（相似信息互相干扰）、删除误伤。

**目标**：借助控制论（LPV、切换系统、卡尔曼/RLS 增益、可观测性、稳定性）重新组织记忆，**保持状态递推线性**，非线性只放在路由、增益、输入特征映射与读出归一化中。

**判断标准**：必须在**等总状态（参数）**条件下比较；收益必须来自组织方式，而非容量。

**关键结论（截至本文件）**：
- 参考模型上，RLS 与内容路由的理论性质已被支持；
- 真实模型上，**删除、训练后的 RLS 优势、等状态分库**三者都还没有被证明。
- 因此，当前最需要回答的问题不是"哪个机制更好"，而是**"在等状态下，组织方式本身是否带来收益"（H10）**。

## 3. 主线（当前唯一的推进链）

```
[真实键诊断 E016]  →  [等状态的组织检验 H10，离线回放 E017 方式]  →  [删除与更新 H12 的闭环修正]  →  [训练检验 H5/H10，等预算]
        ↑ 门控 G0 已通过                    ↑ 门控 G1（当前）                 ↑ 门控 G2                          ↑ 门控 G3
```

只有通过上一门控，才进入下一步。失败则记录为负结果，并回到主线的上一层重新选择。

### 门控定义（预先约定）

- **G1（等状态组织检验，离线真实键）**：在相同总状态下，内容路由（中心化）的分库相对于 K1 单库，自检索余弦的配对差（按写入次数分组）区间不含 0 且为正。若只在 K4（4 倍状态）上成立，则 G1 **不通过**。
- **G2（闭环删除）**：删除后，被删信息的读出接近"从未写入"的参考，且其他条目误伤小（相对阈值待定）。目前 G2 未通过（H12）。
- **G3（训练检验）**：在等训练预算、多种子下，新结构相对原版的验证损失，配对区间不含 0 且为负。E013 的 RLS 在从头训练的设置下未通过（但它是未调参、短训练的结果，需要在 G3 中重新设计）。

## 7. 判断原则（防止发散）

1. 每次实验前，写出它检验的假设编号与判据。无编号的实验不做。
2. 比较必须等总状态（或明确标注容量混杂）。
3. 结果不论正负都要记录（负结果进 `negative_results.md`）。
4. 一个门控未通过，不进入下一门控；不能用后续门控的结果反过来"救"前一门控。
5. 新想法先进 `docs/ideas.md`，附上它对应的假设与判据；只有它能改变某个 H 的状态时，才提升为分支。
6. 理论推断与实验证据必须分开标注（✅ 已验证、⚠️ 条件成立、❓ 未检验、💭 猜想）。
