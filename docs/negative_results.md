# 负结果记录

按 CLAUDE.md，负结果与未达预期的结果同样记录。每条注明实验编号与证据位置。

---

## N1　等参数分库（臂 i）在随机键投影下失去键正交性

- **实验**：E006 M1，ρ=0 时 K=4、d_b=d/4（总状态与基线相同）。
- **现象**：目标与干扰键的余弦为 0（读出应为完美召回，基线 K=1 为 1.00）。分库后召回降至 0.04（n=128）。
- **原因（推断，已有直接证据）**：每库使用固定随机正交投影 $P_b$ 把键压到 16 维。投影后，原本正交的键在库内不再正交，$\kappa_b^\top\kappa_{b'}\neq0$。因此 ρ=0 时仍有串扰。
- **证据**：`experiments/E006_0a_banks/summary.csv`，M1，arm=i，ρ=0.0，n=128。
- **影响**：等参数分库的设计 A 不能使用随机投影。需要重新设计库内键的表示（候选：键维度分块、库内保持完整维度、或其他正交化方式）。

## N2　软路由在未训练的中心下几乎均匀，分库不生效

- **实验**：E006 M1，softmax 路由，温度 τ=1，中心为固定随机向量。
- **现象**：路由熵约 1.38，接近 $\log 4$（最大值）。各库利用率约 0.25。
- **含义**：软路由没有把键分到不同库，写入强度被均分到各库（每库约 $1/K$），这与分库无关，而是有效写入强度的减弱。
- **证据**：E006 M1，arm=i，top_k=softmax，各 ρ 下 `routing_entropy_mean` 约 1.38。
- **混杂**：臂 ii（softmax，全维度）在 ρ=0.1 时召回从 0.20 提高到 0.37，这一改善来自有效写入强度变小，不是分库本身。
- **影响**：路由的温度或学习方式必须在设计中明确。0a 无法判断学习后的路由能否分库。

## N3　显式删除在软路由下不完整

- **实验**：E006 M3，softmax 路由下删除目标（β_d=1）。
- **现象**：目标残留为 0.6–1.0（即删除基本无效）。而 top-1 路由下残留为 $10^{-15}$（完全删除）。
- **原因（已有直接证据）**：删除只作用于按权重的各库，每库只去除 $g_b$ 的部分，而写入时目标被分散到各库。
- **证据**：`experiments/E006_0a_banks/summary.csv`，M3，arm=i，top_k=softmax，`target_residual_mean`。
- **影响**：删除必须使用与写入相同的路由。设计 C 需要规定：要么硬路由，要么按路由质量归一化 β_d。

## N4　分库在相关键下路由塌缩

- **实验**：E006 M1，top-1 路由，ρ 增大。
- **现象**：ρ=0 时最大库利用率为 0.30，ρ=0.6 时升至 0.59。相关键集中到少数库。
- **含义**：路由没有负载均衡，相关键会压垮少数库，这正是 ideas 文件和 design_holistic 中提到的塌缩风险。
- **证据**：E006 M1，arm=i，top_k=1，`max_bank_util_mean`。
- **影响**：设计 E 需要负载均衡正则，并监控利用率。

## N5　快慢双库（随机路由）未优于单库

- **实验**：E006 M2，fast α=0.9 与 slow α=0.999 两库，top-1 随机路由。
- **现象**：age=64 时召回 0.24，而单库 α=0.999 为 0.40。
- **含义**：路由未学习时，目标随机进入快库或慢库，快库的快速遗忘使一半的信息更早丢失。多时间尺度的收益依赖路由能学到正确的分配，0a 无法单独证实。
- **证据**：E006 M2，arm=fast_slow_top1 与 arm=single_0.999。

E006 的首次运行中，M3 的所有结果为 0。原因是 `read` 在批量大小不一致时静默地把状态清零（代码缺陷），而非方法本身的结果。修正为：批量不一致时报错，并增加多查询读出。修正后重新运行，所有结果以修正后的为准。

此外，E006 的基线是 Metis 的 GDN 形式（β=1，带按键擦除），与 E001 的参考形式不同，两者的数值不能直接比较。

## N6　RLS 在遗忘因子 λ<1 时降秩删除不精确（残留增大）

- **实验**：E007 M3，RLS，λ=0.99，删除目标（ρ=0.1）。
- **现象**：目标残留从 GDN 的 $10^{-15}$ 变为 1.6（K1）和 3.8（臂 i，top-1）。`fallback` 计数为 0，降秩条件始终满足。
- **原因（推断，与理论一致）**：降秩（downdate）是 RLS 在 λ=1 时的精确逆。λ<1 时，写入之后的遗忘没有被撤销，而降秩仍按照"未遗忘"的协方差减去目标贡献，结果减过头。
- **证据**：`experiments/E007_rls/summary.csv`，M3，`target_residual_mean`。单元测试 `test_lambda_one_delete_restores_ridge_without_the_item` 只覆盖 λ=1，因此没有捕获这一情形。
- **影响**：λ<1 时不能使用降秩删除。修正候选见 `experiments/E007_rls/README.md`。

## N7　RLS 的提升可能来自额外状态，而非增益调度

- **实验**：E007 与 E006 的对比。
- **现象**：RLS 在所有配置上都优于 GDN，但 RLS 每库多存协方差 $P$（$d_b\times d_b$）。
- **含义**：在没有等状态大小的对照前，不能把提升归因于增益的解析调度。
- **证据**：E007 `README.md` 的"混杂因素"一节。
- **影响**：需要等状态大小的 GDN 对照（见 E007 README 的下一步）。

## 状态更新（2026-10-15）

- **N1**：E008b 证明分块投影与随机投影同样失败。根本原因是等参数分库使目标键与干扰键在库内不再正交（不取决于投影形式）。决定：默认单库；分库保留为满维度键的可选项（K 倍状态）。见 `experiments/E008_controls/README.md`。
- **N6：已解决**。降秩对 λ<1 的精确性需要使用条目的遗忘权重 $\lambda^{\text{age}}$。使用该权重后，删除与参考一致（单元测试）。见 `experiments/E007_rls/README.md`。
- **N7：部分解决**。等状态的 GDN 对照（E008a）下，RLS 的优势仍然存在。GDN 的对照形式还不完整，需要更多对照才算完全解决。

## N8　协方差的迹上界不足以防止 windup（已修正）

- **实验**：E013 的 RLS 训练（种子 1，第 136 步崩溃；种子 0 的 fp64 版本过慢后停止）。
- **现象**：加入迹上界并把求逆改到 fp32 后，仍出现 `linalg.inv` 奇异。
- **原因（模拟，推断）**：迹上界按比例缩放整个 $P$，压缩已激励方向上的特征值，而未激励方向仍然偏大，条件数随时间增长（低秩键时尤其明显）。
- **处理**：改为特征值上界（设计 0a §14），所有 RLS 种子重跑。
- **证据**：`experiments/E013_1b_train/invalid_v4_rls_s1_crash/`、`invalid_v5_trace_clamp_old/`；设计 0a §14。
- **影响**：RLS 的结果依赖这一稳定性约束。该约束在报告中需写明。

## N9　特征值截断的反向传播在初始协方差处为 NaN（已修正）

- **现象**：改为特征值截断后，RLS 第 1 步梯度范数为 NaN，训练按设计停止。
- **原因**：$P_0=kv\cdot I$ 的特征值全部相同，`eigh` 的反向传播除以特征值之差，为无穷大。
- **处理**：截断只用于前向，反向直通（straight-through）。单元测试 `test_gradient_finite_with_repeated_eigenvalues`。
- **证据**：`experiments/E013_1b_train/invalid_v5_trace_clamp_old/rls_s*_eigclamp_nan_grad/`（如存在）。

## N10　RLS 降秩删除在真实 Metis 中不精确（闭环记忆）

- **实验**：E015(b)，预训练 Metis-4B 上 RLS 装入后删除包含答案的 chunk。
- **现象**：降秩后的状态与"从未写入该 chunk"的参考相差很大（较深层约 0.66），而同样输入下的降秩公式误差仅约 $3\times10^{-5}$。
- **原因（已验证）**：记忆是闭环的。较早层的记忆读出改变后续层的隐藏状态，从而改变后续写入的键。删除后，后续写入的输入不再相同，降秩假设输入固定，因此不精确。第 0 层的键不变，第 7 层的键变化，与此一致。
- **修正**：之前在参考模型上得出的"RLS 删除精确"结论只在开环（固定输入）下成立，不能用于训练后的 Metis。
- **状态（用户确认）**：理论未被推翻，问题在于 RLS 不能直接嫁接到 GDN 训练的模型上，需要从头训练。见 `design_0a.md` §15。
- **证据**：`experiments/E015_zero_shot_deletion/README.md`。
- **影响**：设计 0a 的 C 模块需要修订；精确删除需要重算后续 chunk，或把删除纳入训练。

## N11　零样本替换 RLS 不是改进

- **实验**：E015(a)，RLS 直接装入预训练 Metis-4B，不训练。
- **结果**：答案 NLL 为 12.58，预训练 GDN 为 10.14，无记忆为 14.16。
- **原因**：预训练的读出与 GDN 的状态动力学匹配，替换后不匹配。
- **影响**：RLS 必须重新训练才能与原版比较，不能直接替换使用。
- **状态（用户确认）**：此结果只说明零样本替换不可行，不能用于评价 RLS 本身。

## N12　等总状态下，预先指定的内容路由（中心化）不优于单库（G1 未通过）

- **实验**：E018（门控 G1），真实键离线回放，256 维 PCA 键，4 库等总状态。
- **现象**：K4_pca_center 相对单库 K1_full 为 −0.0020（层 3）与 −0.0018（层 7），配对区间均不含 0 且为负。随机分库相比中心化路由没有明显差异（层 7 反而更好）。
- **含义**：在真实键上，等状态的内容分库没有显示收益。E017 中看到的收益来自 4 倍状态（容量混杂）。
- **正面结果**：单库 256 维 PCA 键相对完整键只损失 0.002，说明键投影本身不是障碍（N1 不适用于真实键的 PCA 子空间）。
- **未通过后的处理**：按总纲规则，不用后续结果追认。未中心化路由的探索性优势只能作为新假设，需要新的预先登记门控。
- **证据**：`experiments/E018_G1_equal_state/README.md`。

N12 只适用于**中心化路由**。用户决定路由不做中心化后，新的门控 G1b（E019，新测试数据）通过。N12 的记录保留，不改写。

N10（降秩在闭环中不精确）仍然成立，但它的解决方式已经确定：精确删除用快照加下游重放（E020 机制 B，状态误差 0）。降秩只在被删 chunk 为最后一个时（无下游写入）才精确。

## N13　分库的负载对随机中心的抽取敏感（G2b）

- **实验**：E021，单一随机中心抽取，真实键，未中心化路由。
- **现象**：最大库占 81%，归一化熵 0.49。E019 中三个中心抽取的平均为 0.31–0.37。
- **含义**：未中心化路由的均衡性不稳健。分库的"收益"可能只是一个大库加少量额外状态。
- **证据**：`experiments/E021_G2b/README.md`。
- **影响**：分库的组织收益未确认。需要多中心抽取的稳健性检验，以及负载均衡机制。

## N14　降秩删除在较早 chunk 上失效，并可能数值爆炸（G2b）

- **现象**：机制 A 的状态误差按被删位置为 1.38、1.05、$10^{14}$、0.64、0.0。
- **含义**：降秩不能作为删除机制，即使在分库结构下也一样（与 N10、G2 一致）。
- **证据**：`experiments/E021_G2b/result.json`。

## N13 更新（E022）：负载集中是普遍现象，E019 的"均衡"是平均造成的

- 10 个中心抽取下，最大库占比 0.35–0.93（层 3）、0.34–0.64（层 7）。层 3 有 7/10 的抽取最大库超过一半。
- E019 报告的均衡负载是三个种子占比的平均，掩盖了每次抽取的集中。G1b 的正面结果因此需要负载受控的检验才能解释。
- 证据：`experiments/E022_load_robustness/`。

## N15　数据自适应路由在真实对话键上不优于单库（G1d 未通过）

- **实验**：E024（门控 G1d），LoCoMo 记忆步骤，按对话拆分（5 vs 5），等总状态，3 个种子。
- **现象**：主臂 K4_CL_cons 相对单库 K1_full 为 −0.0010（层 3，区间 [−0.0016, −0.0005]）与 −0.0109（层 7）。两层的 G1d-b 均失败。负载在层 7 为 0.30，层 3 为 0.44（G1d-a 仅在层 7 通过）。
- **与 G1c 的对照**：G1c（合成键）上 CL_cons 优于单库。真实键上未重现。
- **注意**：K4_CL_cons 与 K4_random 基本持平，G1d-c 的通过主要反映 balanced_free 基线较弱（它低于随机分配）。
- **未决的局限**：CL 各臂的最大库占比在 3 个种子之间完全相同，种子效应可能未真正生效，需先确认，才能判断本结论的稳健性。
- **处理**：按总纲规则，不用结果修改判据，不进入 G2c。G1c 的结论仅限合成键。
- **证据**：`experiments/E024_G1d/README.md`、`experiments/E024_G1d/result.json`。
