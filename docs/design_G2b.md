# 设计说明：门控 G2b（未中心化分库接入真实 Metis，组合删除）

状态：自主执行（用户授权，2026-10-16）。判据在运行前登记，运行后不得修改。
依据：`docs/MASTER_PLAN.md`（H10b ✅，H12b ✅），`docs/design_G1b.md`，`docs/design_G2.md`。

## 1. 目的

G2 只在单库 RLS 上检验了删除。G2b 检验"未中心化内容路由 + 分库 + 删除"的组合，在真实 Metis-4B 的闭环中是否仍然精确、可实现，并给出成本。这是按用户意见"先组合再细化"的第一步。

## 2. 结构（等总状态）

- 每层：K=4 库，每库键维度 256（PCA 基 Q，由 seed 9000 的前 10 条 episode 拟合，与 E018/E019 相同），值维度 1024。总状态 4×256×1024 = 1024×1024，与单库相同。
- 路由（不中心化，与 G1b 相同）：`argmax_b (k̂ · c_b)`，k̂ 为单位化的完整 1024 维键，c_b 为随机固定中心（位于 PCA 子空间内）。不使用数据统计量。
- 写入：每个 token 按路由分配到一个库；每个库对 chunk 做一次 RLS commit（权重为指示值，只有路由到该库的 token 为 1）。
- 读出：查询 token 按同一路由选库，读出该库的归一化结果（与 G1b 的 `simulate_raw` 相同）。
- 更新规则：RLS（λ=0.9，单位键，P0=I，与 E019 一致）。

## 3. 与 Metis 的接口

- 通过 monkeypatch 替换每层的 `local_memory` 读写方法与 hyper memory 的 `_apply_gated_delta_rule_update`，与 `src/holistic/rls_metis.py` 的做法一致。
- 不修改 `metis/` 下的代码。卸载后恢复原版（回归测试）。
- 状态在 `lm` 上以 `_bank_states` 列表保存（每库的 M、P、z），由 `get/set` 函数读写快照。

## 4. 删除机制（与 G2 相同的两种）

- **A 降秩（近似）**：按每库、每 token 的写入权重 $\lambda^{\text{age}}$ 降秩。
- **B 快照加下游重放（精确）**：恢复被删 chunk 之前的快照，以零权重重放被删 chunk，再重放之后的 chunk。
- 参考：会话从头以零权重的被删 chunk 重放（gold）。

## 5. 数据

- 测试：seed 9300，20 条新 episode（与 E018–E020 不重复）。
- 被删 chunk：包含答案的最后一个 chunk。

## 6. 判据（预先登记）

- **G2b-0 实现回归**：当 K=1 且不做 PCA（Q 为单位阵）时，分库实现与原版 RLS（`install_rls`）的状态逐位一致（一条 episode）。这是实现正确性的前提，失败则停止。
- **G2b-1 精确删除**：B 的状态误差（所有库、所有层）< $10^{-3}$，每条 episode。
- **G2b-2 删除有效**：B 的答案 NLL 与参考的配对差（区间）在 [−0.1, +0.1] 内。
- **G2b 通过**：G2b-0 与 G2b-1 与 G2b-2 同时满足。
- A 只报告误差（按被删位置），不参与通过判定。
- 同时报告：各库的负载（最大占比、归一化熵）、成本（重放 chunk 数、快照显存）。

## 7. 局限（预先声明）

- 零样本：分库结构没有经过训练，与预训练的读出不匹配（E015a 的发现）。因此本门控只检验**组合的删除机制**，不评价回答质量。
- 答案 NLL 的分辨力不足（E020）。
- 自检索和 NLL 都不是问答正确率。
